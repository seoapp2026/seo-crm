3.2. COMPETITOR AUDIT & CRM ACTIVITY TRACKING
• Competitor Intelligence System:
  - 3 Active Competitors monitored simultaneously per project.
  - Historical Competitor Archive / Library: Rotate active competitors without losing historical data, notes, or learnings.
  - Competitor Profile Schema: URL, Name, Date, Executive Summary, Strengths, Weaknesses, Opportunities, Identified Improvements.
  - On-Demand URL Deep-Scan: Analyze visible web elements (structure, page types, blog posts, reviews, FAQ, CTA buttons, UX layout, detectable technology stack).
• Core Tracking Framework:
  WHAT WAS DONE → WHAT WAS DISCOVERED → WHAT CHANGED → WHAT RESULT IT PRODUCED → WHAT IS MISSING → NEXT ACTION.
• Metric & Activity Separation:
  1. Business/SEO Performance Metrics: Traffic, SERP Rankings, Impressions, CTR, Leads, Conversions, Sales Revenue.
  2. CRM Internal Activity Log: Scraping jobs run, competitor audits completed, keyword clusters generated, content drafts pushed, automated tasks executed.

3.3. WORDPRESS INTEGRATION & WORKFLOW SPECIFICATION
• Explanatory Framework for Non-Technical End Users:
  WHAT WE HAVE → WHAT I CAN DO → WHAT I CANNOT DO → HOW I WOULD WORK → WHAT REMAINS PREPARED FOR LATER.
• Product Connectors & Catalog Scope:
  - Scrape/Research product data, specifications, and prices.
  - Generate formatted affiliate references (e.g. AAWP shortcodes, Amazon Product Advertising API payloads, custom schema cards).
  - Synchronize draft articles, landing pages, and WooCommerce product entries via WordPress REST API / Application Passwords without breaking existing templates.
  - Maintain CSV/JSON import/export interoperability.

3.4. SYSTEM ARCHITECTURE & ROLES
• CRM: Operational engine, automated scraper, database of keywords, SERP clusters, and backend task execution.
• Notion: High-level visual dashboard, project and task management, strategic decisions, prompt library, and knowledge documentation.
• Make / n8n: Automation middleware, webhook listener, and data transformation pipeline.
• WordPress: Public website publishing engine, customer-facing content, and eCommerce storefront.
• Future ERP: Extended business modules (Invoicing, Clients/CRM, Accounting, Inventory/Warehouse, Purchasing).
• Core Integration Principle:
  "NOTION ORGANIZES / PROPOSES → CRM VALIDATES / EXECUTES"
  (Notion does NOT directly mutate raw technical fields, database primary keys, or internal scraping logic).

3.5. THE 10 TECHNICAL ARCHITECTURE QUESTIONS (SUMMARY)
1. Will the CRM offer an open REST API to pull and push data?
2. Can the CRM trigger and receive Webhooks upon state changes?
3. Can the CRM integrate seamlessly with Notion databases in the future?
4. Can Make or n8n connect to the CRM without modifying core backend code?
5. Can the CRM connect with WordPress via REST API / Application Passwords?
6. Which capabilities are straightforward integrations vs. full custom modules?
7. What technical structures should be prepared right now to avoid future rewrites?
8. Can future integrations and connectors be rolled out incrementally in phases?
9. Will future modules have an independent cost separate from the current Phase 2 build?
10. Is the current architecture modular enough to scale into a full ERP system without rebuilding from scratch?
