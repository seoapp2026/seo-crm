
Will the CRM be yours?
Yes. This is a custom project built for you, not a rented tool that only works inside one company platform. When the work is properly handed over, you should have access to the code, the database, and the configuration needed to run it. You will not be locked out of your own product.

Is it portable like WordPress?
Yes, the idea is the same. With this CRM you keep the application code, the database with all your data, and a short list of settings (API keys, domain, database connection). If one day you change hosting or developer, you can take that copy, put it on another server, and run the CRM again without building it from zero. You may still need a technical person to help with the migration, just like with WordPress sometimes, but it is a move, not a full rebuild.

What will you actually have?
On a day-to-day basis, the live CRM runs on hosting (for example Railway today), and the code is stored on GitHub. GitHub is like a secure folder with history for the code: every update is saved there, you can download the full project anytime, and another developer can continue from that copy later. Your real CRM content (projects, keywords, notes, and so on) lives in the database, so that must be backed up separately. Best practice is the same as WordPress: keep a copy of the code and a copy of the database on your computer or hard drive from time to time.

Where things live, in simple terms:
Code: GitHub (you should have owner or admin access).
Live website and database: hosting account (you should control or co-own that account).
API keys and Google or OpenAI accounts: always under your accounts.
Backup on your hard drive: full code download plus database export, when we set that up as part of delivery.

Can you switch providers later?
Yes. The process is: export the database, download the code from GitHub, create a new hosting and database, restore the backup, deploy the same code, and reconnect your settings and domain. You are not tied forever to one host or one person. You are free to move and free to hire someone else later using the same project.

About the timeline (two or three months):
Two to three months is a reasonable planning window for a solid, usable CRM with the main SEO workflows, as long as the scope stays focused and external approvals from Google progress normally (for example Ads API access and domain verification). The work is delivered in phases, not as one single surprise at the end.

What is already largely in place:
The core CRM structure (projects, niches, pages, keywords, URLs, links, notes), dashboard, AI content drafts for you to review, Google Search Console and Analytics connection path, and the live project on hosting with code on GitHub.

What still depends on next steps and external processes:
Full Google Ads keyword data sync (Google must approve the developer token), production Google branding on a domain you own (not only a Railway free subdomain), final polish, and a clean handoff package.

What “finished” should mean for you:
1) You can use the CRM in your daily SEO work.
2) You have access to the code on GitHub.
3) The database can be exported and you know how to back it up.
4) You receive a simple written guide: how to log in, where settings are, how to back up, and how to redeploy.
5) We list any later improvements separately, so they are not mixed with “core complete.”

For your peace of mind, I recommend we confirm three things as we finish delivery:
You are owner or admin of the GitHub repository.
Hosting is under your account 
We set a simple backup habit: periodically save code and database export to your hard drive or cloud storage.

In short: the CRM is designed to be yours, portable, and movable. GitHub protects the code. The database holds your data. Together they work like a WordPress-style full backup. You will not need to develop the product again from scratch if you change host or vendor later.
