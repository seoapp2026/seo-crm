TECHNICAL AND WORKFLOW ANSWERS: WORDPRESS EXPORT, MASTER PROMPTS, AND DIVI LAYOUT STRUCTURING

PART 1: HOW DOES WORDPRESS EXPORT CURRENTLY WORK?

In the current CRM version, the WordPress export bridge (/wordpress) works as a structured export under a human-supervised workflow (to prevent accidental automated publishing of unreviewed content):

1. What it currently generates:
   Exports a downloadable JSON file (or copyable to clipboard) containing the list of pages for the selected project.
   Fields included per page:
   * Page title (title)
   * URL slug (slug)
   * SEO Meta Title (meta_title)
   * SEO Meta Description (meta_description, based on page objective)
   * Page content type (content_type: TSG - Info Guide, TSR - Comparison/Roundup, TSA - Product Review)
   * Main heading (h1)
   * Workflow state (status: draft, in_review, published, optimized)
   * Niche / Category (niche_name, which maps directly to WP Category)
   * Export timestamp and project metadata (exported_at, project_name)

2. What is missing today for full post content inside that JSON:
   Currently, the exporter exports the architecture and SEO metadata. AI-generated text bodies live in the content drafts table (content_drafts).
   Merging the final structured body (content_html / content_divi) into this export JSON is a straightforward, direct enhancement.


PART 2: ANSWERS TO YOUR 6 QUESTIONS

1. Can I create new assistants/prompts from the CRM UI, or do you need to modify the program?

CURRENT STATUS:
There are currently 5 predefined assistant slots in the database (SEO Architect, Keyword Classifier, Content Generator, Competitor Analyst, Continuous Optimizer).
From the "Prompt Editor" screen (/prompts), you can freely edit the System Prompt text, description, and AI model (gpt-4o-mini, gpt-4o) for these 5 assistants, and changes take effect immediately on subsequent runs without touching code.
However, adding a 6th or 7th separate tab/button currently requires a code modification because the initial configuration used a fixed 5-value enum.

WHAT WE CAN DO:
Enable a "Dynamic Prompt Library" with a "+ Create New Prompt / Assistant" button, allowing you to create, name, and manage as many prompts as you want directly from the user interface without requiring future code changes.


2. I have 11 master prompts + Prompt 00 (niche validation). Does the current architecture allow them without rewriting the CRM?

YES, 100%. NO REBUILD OF THE CRM IS REQUIRED.
The backend architecture (FastAPI + SQLAlchemy) and frontend architecture (modular React) are clean and decoupled.
To expand from 5 to 12 (Prompt 00 + the 11 master prompts), we simply relax the prompt identifier in the database to accept dynamic slugs and add standard creation endpoints.
All existing features (automatic injection of project, niche, page, competitor, and metric context) will work identically for all 12 prompts.


3. LAYOUT / STRUCTURE: Specific Layout Assistant/Prompt that outputs formatted content (sections, H1/H2/H3, CTAs, tables, callout boxes, images, FAQs, products, CSS classes/HTML).

FULLY FEASIBLE AND THE RECOMMENDED APPROACH.
Workflow:
1) The initial prompts generate the raw research, keywords, facts, and SEO copywriting.
2) The "Layout Prompt" receives that copy + the project's design guidelines and transforms it into clean, semantic HTML with predefined CSS classes (e.g., <div class="featured-box">, <table class="comparison-table">, <div class="affiliate-cta"><a class="btn-buy">...</a></div>, FAQ accordions, etc.).
AI models excel at converting plain text into structured HTML elements with standard styling hooks.


4. Can we include that structured output in the export JSON so WordPress/Divi imports ready-to-use pages according to a template?

YES.
We add a "content_html" (or "post_content") field to the export JSON containing the fully structured markup.
Automated import methods in WordPress:
* RECOMMENDED METHOD (WP All Import): Using the WP All Import plugin, you upload the exported JSON and map the fields once (Title -> Title, Slug -> Slug, Meta -> Yoast/RankMath, content_html -> Post Content, Niche -> Category). Upon import, the page is created and formatted 100% according to the template.
* REST API METHOD (Future optional): A "Push to WordPress" button inside the CRM that uses WordPress REST API with application passwords to create draft or published pages directly.


5. If Divi needs another format besides HTML/JSON, what is the right format and what changes are needed in the exporter?

HOW DIVI WORKS AND THE BEST STRATEGY:

Divi supports two primary ways to receive structured content:

A) APPROACH 1: Structured HTML + Divi Theme Builder (CLEANEST AND RECOMMENDED)
How it works: In WordPress, you set up a global post/page template in "Divi Theme Builder" for the niche (header, sidebar, typography, CTA button colors, table styles, callout box styling).
The CRM exports standard semantic HTML using the corresponding CSS classes.
Advantages: Ultra-fast loading speed, 100% clean code for Google (best SEO performance), immune to Divi core updates, and changing the global niche design instantly updates all pages.

B) APPROACH 2: Divi Native Shortcodes in post_content
Divi stores visual builder modules in post content using internal shortcodes (e.g., [et_pb_section][et_pb_row][et_pb_column][et_pb_text]...[/et_pb_text][/et_pb_column][/et_pb_row][/et_pb_section]).
If you need each block to open as a visual, draggable Divi module inside the Divi Visual Builder, the Layout Prompt can be configured to wrap sections in native Divi shortcode syntax.

In the CRM exporter, we can provide a format toggle:
* "Export as Structured HTML (Theme Builder)"
* "Export as Native Divi Shortcodes"


6. Can we save a design template per project so all pages in a niche keep the same aesthetic and structure?

YES, ABSOLUTELY.
We can add a "Design / Layout Template" field or tab to each Project or Niche in the CRM.
There you define the visual skeleton of the niche (e.g., heading hierarchy, CTA callout box format, comparison table structure, pros/cons layout, affiliate shortcode format like AAWP).
When you run the Layout Assistant for any page in that project, the CRM automatically feeds this blueprint into the AI prompt context, ensuring 100% of the articles in that niche follow the exact same visual identity and structure.


SUMMARY OF THE COMPLETE END-TO-END FLOW

1. Data & Niche (CRM): Project selection, niche, keywords, and live metrics.
2. SEO Prompts (00 to 11): Research, search intent, enriched draft copywriting.
3. Layout Prompt: Combines draft content + project design template -> outputs structured HTML/Shortcodes.
4. JSON Export: Generates complete bundle (title, metas, slug, H1, categories, structured content).
5. WordPress / Divi: Direct import with the page completely formatted and ready for publishing.
