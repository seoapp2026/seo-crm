4) How to install the app on another hosting

In simple steps:

1. Get the full code from GitHub (or a full code backup zip).
2. Create a new hosting service that can run Docker (recommended) or Node + Python.
3. Create a PostgreSQL database on the new host.
4. Set the environment variables (database URL, secrets, domain, API keys).
5. Deploy using the project Dockerfile (one service builds frontend + backend together).
6. Point your domain to the new host and update the public URL / OAuth redirect settings if needed.
7. Run/start the app and check the health endpoint.

Current production uses Docker on Railway, which makes install elsewhere straightforward on any host that supports Docker and PostgreSQL.

5) How to move or restore without losing data

You need both pieces every time:

A) Code backup: download from GitHub (or keep a zip of the repository)

B) Database backup: export/dump of PostgreSQL (this holds projects, keywords, notes, pages, etc.)

Move / restore process:

1. Export the database from the old host (pg_dump / host backup tool).
2. Create a new empty PostgreSQL database on the new host.
3. Restore the dump into the new database.
4. Deploy the same code version.
5. Point DATABASE_URL (and other env vars) to the new database.
6. Start the app and verify login and data.

If you only move the code and forget the database, the screens come back empty. If you only move the database and forget the code/config, nothing runs. Both matter.

7) Versions, parameters, database, and config

Stack (main pieces):

Backend: Python 3.13, FastAPI, SQLAlchemy, Uvicorn
Frontend: React + Vite (Node 22 to build)
Database: PostgreSQL 16
Deploy: Docker (Dockerfile included), currently Railway

Important configuration (environment variables), not hard-coded secrets:

DATABASE_URL: connection to PostgreSQL
SECRET_KEY: app secret for sessions/tokens
APP_PUBLIC_URL: public site URL (e.g. https://crmpersonal.es)
CORS_ORIGINS: allowed browser origins
APP_AUTH_PASSWORD / AUTH_ALLOWED_EMAILS: login gate
OPENAI_API_KEY: AI features
GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET / GOOGLE_REDIRECT_URI: Google login/integrations
Other Google-related settings as needed (Search Console, Analytics, Ads when approved)

These live in hosting environment variables (and a local .env for development). API keys and Google/OpenAI accounts should always stay under your ownership.
