2. LOGIN / LOGOUT / SESSION (full auth gate)
================================================================================

How login works (short):
  - If APP_AUTH_PASSWORD is set on Railway, the CRM requires login.
  - Email + password form posts to /api/seo-crm/auth/login
  - Server sets httpOnly cookie seo_crm_session (about 7 days)
  - Protected API routes return 401 without a valid session
  - Frontend RequireAuth sends you to /login if not authenticated

2.1 Wrong password
  [ ] Go to /login

9. AI — HOW IT WORKS (read once)
================================================================================

Pipeline:

  Your CRM data (pages, keywords, notes, competitors)
        +
  Synced Google data in YOUR database
        (GSC / GA4 metrics; Ads volumes in Keywords Ads)
        ↓
  You click Generador IA or an Asistente
        ↓
  Backend builds a text prompt from that context
        ↓
  OpenAI (OPENAI_API_KEY on server only)
        ↓
  Draft / analysis shown in UI
        ↓
  YOU review → copy → publish manually (WordPress is manual)

What each AI entry uses TODAY:

  Generador IA
    - Selected page (title, type TSG/TSR/TSA)
    - Niche
    - Keywords assigned to that page
    - Does NOT auto-pull Ads rows yet
    - Best Ads workflow: sync Ads → prioritize keywords → assign to page → generate

  Asistentes IA
    SEO Architect          → niche / structure context
    Keyword classifier     → niche / page + keywords
    Content generator      → page + keywords + GSC/GA4 page metrics if available
    Competitor analyst     → competitor + page/niche
    Continuous optimizer   → page + GSC/GA4 performance if available

  Ads + AI practical loop
    1) Sync Keyword Planner
    2) Read volume/competition/CPC in Keywords Ads
    3) Put best keywords on the right page
    4) Run Generador IA or Content generator
    5) Optional: paste Ads numbers into “extra context” on Assistants

AI never:
  - publishes to WordPress alone
  - creates Google Ads campaigns
  - exposes API keys in the browser
